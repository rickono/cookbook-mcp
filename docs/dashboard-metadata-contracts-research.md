# Dashboard metadata contracts and observation gaps

Research for [Establish the dashboard metadata contracts and observation gaps](https://github.com/rickono/cookbook-mcp/issues/79), under [Specify the local read-only cookbook dashboard](https://github.com/rickono/cookbook-mcp/issues/78). Investigated 2026-10-31 against repository revision `0384b358d2f51e5ef2ad54c64e72f4291366adf0`. Code links below pin that revision. This is factual research and a proposed adapter contract, not approval of dashboard policy or implementation.

## Scope and evidence discipline

Standing owner scope: a local read-only dashboard covers all intended books, including pending and held books, with inventory, processing, review, errors, publication availability and freshness. Retrieval analytics must be specified and may follow inventory/status delivery. Membership rules, status vocabulary, architecture/freshness guarantees, metric definitions, experience and acceptance remain the other map tickets' decisions.

The private starting plan, audit JSON, inventory CSV, hosted-observation JSON and audit script were read. The script was inspected as text, never executed or imported. Bounded linked metadata was checked using standard-library JSON and read-only SQLite transactions. Recorded JSON digests were rechecked; the retained manifest digest matched its pointer; the retained index's catalog identities matched the saved hosted observation. These checks establish agreement of retained evidence, not a fresh network observation, content validity or proof of approval. The CSV and draft plan are derivative evidence, not independent authorities.

Only structural findings are published here. Private titles, IDs, hashes, paths, counts and operational receipts remain private. No source book, page image, page/section transcription file or provider reader was accessed; no pipeline/helper/status script was invoked. No ingestion, rendering, OCR, inference, credential acquisition, worker/review/hold/selection change or publication occurred. The existing fail-closed Linux VM/cgroup admission is preserved; a dashboard refresh must never enter those execution paths ([resource boundary](ocr-resource-isolation.md)).

## Verified observation gaps and objections to the draft

The inspected one-off evidence has no common schema contract: selection receipts carry approved/held references, scope and recorded time; batch manifests carry a batch namespace, authorization, creation time and source registrations; separate source receipts carry source digest/format metadata without necessarily a library path; admission receipts carry checked time, snapshot proof, candidate/parent/source digests, coverage, content-approval/build-selection fields and source-review limits; quarantine inventories carry checked time and affected-page evidence. Their field names are observations, not reusable authority guarantees. Admission is not complete-content approval. The inspected admission receipt's presence does not validate its candidate payloads or establish current serving status. Retained-build receipts bind a local build path to publication/manifest identity; activation claims still need an independent runtime observation.

1. **Intent is distributed.** The bounded evidence contains publication selections, owner holds and a separate processing registration. No universal intended-book registry was established in this scope. Current versus frozen catalog discovery differs; absence from a catalog or publication cannot alone establish exclusion. A private registration's numeric ID also exists in the catalog namespace. Proposed registry seeding must preserve evidence and undecided discovery; the owner still chooses membership/edition display rules.
2. **Coverage is a claim within a generation.** Inspected historical candidate metadata declares complete transcription while linked quarantine metadata records affected pages. The progress helper literally counts page-cache file existence as `transcribed` ([progress](https://github.com/rickono/cookbook-mcp/blob/0384b358d2f51e5ef2ad54c64e72f4291366adf0/scripts/reader_bench/production.py#L180)). Neither can establish successful, usable or approved content. The quarantine receipt is historical evidence, not a supported current-status service. Full present refusal clearance was not verified; no text or source experiment was attempted.
3. **Refusal, uncertainty and technical failure differ.** Triage distinguishes terminal unavailability, exhausted allowance, uncertainty, timeout, interruption and technical failure ([classification](https://github.com/rickono/cookbook-mcp/blob/0384b358d2f51e5ef2ad54c64e72f4291366adf0/scripts/triage_reports.py#L278)). Recovery bookkeeping uses ordered SQLite events, overlapping source/page regions and persisted alias lineage; its constructor creates state, so do not instantiate it for dashboard reads. Its status is attempt history, not worker liveness ([recovery](https://github.com/rickono/cookbook-mcp/blob/0384b358d2f51e5ef2ad54c64e72f4291366adf0/src/cookbook/recovery.py#L30)). The durable private recovery database was not part of this inspection. Do not infer that newer text clears terminal evidence or recommend a retry from a coverage gap.
4. **Owner work spans stores.** The bounded triage decisions contain owner work absent from the inspected build queue. Copied decisions must not inflate backlog; identical report IDs count once, while differing outcomes require reconciliation. Backlog must separately describe untriaged reports, decided human edge cases and unapplied/ambiguous corrections. Local historical report stores cannot establish current remote arrivals.
5. **Catalog membership is weaker than current access.** The audit records catalog presence without indexed text; this research verified index/catalog identities but did not inspect section text to revalidate that content claim. The serving code independently suppresses superseded/withdrawn content and applies approval eligibility ([library eligibility](https://github.com/rickono/cookbook-mcp/blob/0384b358d2f51e5ef2ad54c64e72f4291366adf0/src/cookbook/library.py#L73)). Catalog queries do not apply the fulltext suppression path ([catalog/fulltext](https://github.com/rickono/cookbook-mcp/blob/0384b358d2f51e5ef2ad54c64e72f4291366adf0/src/cookbook/library.py#L226)). Display publication membership separately from indexed coverage and current restrictions; no source-content probe is authorized here.

Read-only MCP annotations describe behavior, not a least-privilege metadata scope. The existing scope also permits source-reading tools and report submission. A dashboard adapter needs a strict method allowlist. Runtime construction/activation/resume and recovery/triage constructors are unsuitable observation shortcuts because they can create directories, restore or rename state. Read configured metadata directly, without importing execution entry points.

## Proposed adapter contract for downstream decisions

This section proposes an implementation seam, not an owner-approved durable schema. Each fact should carry:

```json
{
  "registration": {"namespace": "synthetic:batch-A", "record_id": 17},
  "edition_ref": "synthetic-edition-A",
  "scope": {"candidate_ref": "synthetic-candidate-A", "publication_ref": null},
  "field": "declared_transcribed_pages",
  "value": 12,
  "denominator": 12,
  "source_ref": "synthetic-evidence-A",
  "schema_version": "dashboard-fact.proposal-v1",
  "event_at": null,
  "observed_at": "2030-01-02T03:04:05Z",
  "validation": "metadata_only",
  "observation": "historical",
  "unknown_reason": null
}
```

Real private edition references should retain trusted source digests, with format and aliases, rather than hash books during refresh. Missing hashes require provisional namespaced identity. Separate intent/hold, processing, review/eligibility, publication membership, restrictions, report state and freshness; one “complete” flag loses information. Preserve all evidence references and applicable scopes. A synthetic second registration `synthetic:catalog-B/17` must remain distinct despite sharing the integer.

Adapter inputs should be explicitly configured roots/records, not recursive discovery of experiments. Validate supported versions, required types, nonnegative counts, denominators, digest syntax and joins; reject paths outside allowed roots and symlinks. Hash permitted metadata only. Missing additive summary tables in older publications mean unavailable summary capability: the current aggregate helper returns zeros for absence, so adapters must not mistake those zeros for observed zero workload ([additive behavior](https://github.com/rickono/cookbook-mcp/blob/0384b358d2f51e5ef2ad54c64e72f4291366adf0/src/cookbook/library.py#L131)). EPUB structure counts are not comparable physical-page transcription percentages.

Use each source's own ordering: ledger decision time plus ID, review predecessor chain, recovery event sequence, and report creation time plus report ID. Selection receipt times and quarantine check times describe their own scope only; records without event time stay null. File modification time, `latest` filenames and higher coverage do not establish authority. Capture observation time separately and preserve conflicts instead of picking the newest file universally.

On permission, validation, read or pagination failure, retain the last successful private snapshot with its success time and record the failed attempt/source and bounded error category. Never turn a failed observation into zero reports, exclusion, unrestricted access or worker completion. Refresh cadence, stale thresholds, retention and atomic snapshot design remain architecture decisions. Worker activity stays unknown without a separately specified reliable heartbeat; PID/cache existence is insufficient.

Synthetic acceptance cases for later implementation: an intended unprocessed book remains visible; namespaced integer collision stays separate; aliases share edition coverage without double counting; a newer candidate does not inherit publication approval; complete declared coverage coexists with terminal refusal conflict; copied decisions count once and conflicting copies are exposed; an empty build queue coexists with triage owner work; missing summary capability is unknown; catalog membership coexists with unavailable content; expired auth/failed withdrawals/backlog reads retain dated facts and expose uncertainty. These are proposed checks, not tests executed here.

## Retrieval analytics: specified gap and required future evidence

The inspected server/library has no durable retrieval event writer or per-book usage store. Existing telemetry emits only fixed event names, deliberately excluding identifiers, URLs, exceptions and request data ([telemetry](https://github.com/rickono/cookbook-mcp/blob/0384b358d2f51e5ef2ad54c64e72f4291366adf0/src/cookbook/telemetry.py#L1)). Historical per-book usage is unknown; catalog/index sizes and cached files cannot reconstruct it. Infrastructure logs outside this bounded investigation were not inspected.

Before metrics can be implemented, specify an event contract with unique event ID, collection start/coverage intervals, schema version, event time and ingestion time, tool/operation, success/failure, publication and source binding, relevant book aliases and optional section/page identifier. Define retry/deduplication, pagination, empty results, failures and alias attribution. Search result exposure, successful content reads and recipe-card presentation are different candidate measures; the metrics ticket must choose their meanings. Avoid raw queries, passages, credentials and unnecessary person identifiers. A metadata-only event reader, aggregation window/timezone, retention/privacy rules, outage intervals and a recording validation plan are still needed. An empty count is meaningful only inside a verified collection interval; before collection and during unmeasured gaps show unknown. No telemetry collection was added by this research.

## Handoff and explicit limits

The present code supports publication/catalog observations and rich local provenance, but no single read-only interface covers intended inventory, worker liveness, current withdrawals, remote report backlog and retrieval analytics. A durable intent/run registry and safe metadata projections are proposals requiring the other tickets' decisions. One-off selections, admission/quarantine receipts and hosted snapshots should be supported as dated evidence adapters, not elevated to perpetual authorities.

Unverified: current hosted publication or access restrictions; remote report backlog; live worker state; full candidate payload validity/content completeness; present recovery/refusal state; complete-content review of the private library; deployment/source parity; standalone authentication/provider configuration. Prohibited content work would be required to prove some of these, so those investigation lines stopped at metadata/code. No human policy ticket is answered or resolved by these findings.
