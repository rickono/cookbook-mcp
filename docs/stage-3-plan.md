## Rollback, failed activation and deletion

A failed upload/verification does not change the pointer. A failed runtime stage leaves its prior local index usable. An unconfirmed activation preserves both prior and staged objects, blocks retention pruning, and is reported as pending/failed rather than successful. Roll back only to a retained, fully verified manifest and confirm the hosted active ID.

Before approved resource deletion, verify a complete independent export, identify all retained publications, and explicitly approve the resources/data to remove. Removing a Fly Machine/volume loses only reconstructable runtime state; deleting the R2 bucket loses durable backup history. Stolen-writer deletion protection remains a separate storage-policy decision. No cloud deletion or real-data garbage collection is enabled by Stage 2.
