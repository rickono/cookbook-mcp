# Library interfaces and source-reading limits for the browser reader

Research for [Establish the library interfaces and source-reading limits available to a browser reader](https://github.com/rickono/cookbook-mcp/issues/88), under [Specify the personal browser library reader](https://github.com/rickono/cookbook-mcp/issues/87). Observed 2026-11-01. This establishes capabilities and prerequisites, not owner preferences or an implementation architecture.

This is connected-client exposure, not evidence that the server lacks them: [server source][server] defines them, and [the whole-book rollout resolution][rollout] explicitly requires metadata refresh to discover the four richer tools. ## Fidelity, uncertainty and version-bound reading

Legacy citations retain publication/book/source IDs, source hash, section/page locator and extraction version; scanned units add transcription labels, ordered correction references and check regions. A check region supplies `physical_page`, normalized `box`, and `state` (`unresolved` or `crop_confirmed`); unresolved markers retain their ID/code. These are distinct from approval. `get_book` supplies declared page-status/unresolved counts. Native citations additionally bind model snapshot and target; source-part citations include document/resource location, reading occurrence and exact boundaries. Retained image placement and parsed body text do not establish image-text readability, semantic completeness or source-identical layout. [Citations and scan reading][legacy-read], [native model][model], [contract][contract]

The combined source computes `eligibility` and reasons, checks current withdrawals at serving time, suppresses withdrawn/superseded legacy text and search hits, and preserves original-page access. Legacy unapproved transcription can still be served with an ineligible reason; an `eligible: false` flag is not equivalent to unavailable text in every case. Suppression happens after the legacy search page is selected, so short/empty pages with a continuation are possible. Do not discard the metadata, infer that all returned content is approved, or relabel a correction as complete-content approval. Nonempty withdrawal enforcement is synthetic test evidence, not a new production withdrawal observation. [Serving rules][eligibility], [search][legacy], [deployment limitations][runtime]

Pin every follow-up to returned identifiers. Legacy offsets stay within the selected publication; native cursors bind publication, model snapshot, book, target and selected parts, rejecting foreign continuations. Retained versions resolve exact citations while available; unavailable publications return `unavailable_publication` rather than substituting current text. Retention is finite, not an eternal-link guarantee. Dynamic withdrawal checks can change availability of text even for retained immutable publication bytes. A bookmark/update policy therefore remains an owner decision. [Cursor validation][model], [publication resolution][publication], [error mapping][server], [withdrawal rules][eligibility]

## Bounded page/zoom support and the separate incident

The server source supports `region=[left,top,right,bottom]`, page fractions with top-left origin and minimum side 0.02. Output `edge` is 256–1,600; region zoom renders the whole page at up to 2,400 before cropping, so a small box does not guarantee high source resolution or low decoder cost. Check-region boxes can be passed unchanged where that argument is exposed. The connected schema here omits it. [Region validation][regions], [page code][page]

Serving admits one render at a time; concurrent requests return `render_unavailable`. A fresh Linux decoder has 128 MiB address-space, 10 CPU-second and 16 MiB output-file limits, plus a 15-second process-group deadline; warnings and invalid output are refused. Originals larger than the 512 MiB cache budget are also unavailable through that cache. These serving limits do not replace the OCR VM/cgroup boundary. No ceilings were changed in this research. [Page/cache code][page], [documented containment][runtime]

[Investigate and bound the hosted high-resolution zoom stall][incident] remains **open**. Its latest first-party resolution evidence documents bounded refusal of expensive pages and continued responsiveness, but does not establish the historical stall's cause. Smaller output dimensions do not guarantee less decoding memory. A later passive capture saw no stall and cannot prove its cause or absence under other workloads. Browser acceptance must include graceful busy/unsupported-page errors; do not promise every scan can be shown, describe the original incident as fixed, or silently retry at greater cost. This research neither reproduces nor resolves that investigation. [Containment evidence][incident-containment], [latest passive observation][incident-latest]

## Remaining decision inputs and prerequisites

1. **Search coverage/UX:** decide whether and how the reader exposes both search paths, categories, candidate states, short/cutoff results and differing rank/grouping rules. No evidence requires a second index. Rich search and scanned search are not parity interfaces. [Native][native], [legacy][legacy]
2. **Browser integration verification:** establish actual tool discovery/region support for the chosen client/server path; test source-safe synthetic TOC, text/related continuations, version errors and image delivery across desktop/phone/tablet. This session proves metadata access and schemas only; it does not prove a browser transport, cross-origin configuration or responsive reader UI. [Observed boundaries above; server contract][server]
3. **Context and fidelity:** decide how readers navigate source divisions/documents and unresolved navigation, see scan labels/check regions, and handle deliberate renderer refusals. No general chapter expansion or guaranteed scan render was verified. [Model][model], [incident][incident]
4. **Publication updates/personal state:** choose current-versus-pinned reopening, stale/unavailable bookmarks, correction/withdrawal presentation, and whether notes/progress/downloads belong in scope. Research establishes locator constraints, not those preferences. [Publication][publication], [model][model]
5. **Dashboard boundary:** the separate [dashboard implementation resolution][dashboard] describes a local metadata-only observer. Read-only inspection of the parent's user documentation agrees: its remote reader calls only publication info and catalog search. That uncommitted implementation was not copied or treated as a hosted content API. Whether to integrate remains the owner's decision.
