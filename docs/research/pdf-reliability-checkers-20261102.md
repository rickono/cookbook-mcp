## Verified OpenAI API facts

[Decisions](https://developers.openai.com/api/docs/guides/decisions) is generally available at `POST https://api.openai.com/v1/decisions`, currently only with `gpt-6-luna`. Text, images and JSON can supply shared evidence; questions produce predicate probabilities, fixed choices or ordered scores. Choice and score include distributions and confidence; a score is a weighted level index, not a fraction of correct text. Files/PDFs and audio are unsupported. Question instructions can contain images. The guide advertises roughly 10× faster decisions than Responses, not a measured result for this pipeline. Uncached input is $0.10/M tokens, output uncharged; cache reads/writes, regional premiums and long-context multipliers affect billing. Shared-prefix caching starts at 1,024 tokens and excludes questions. Usage exposes cached and written tokens within input totals. These are documentation facts, not a cost estimate or access verification.

The [create reference](https://developers.openai.com/api/reference/resources/decisions/methods/create) accepts 1–400 questions, 2–255 choice values and 2–10 score levels. Images use inline base64 data URLs or publicly accessible HTTP(S) URLs, not file IDs. `detail` accepts low/high/auto/original according to the model image profile. JSON data is limited to 32 container levels, 10,000 values and 256 KiB compact UTF-8. Any question may return `type: refusal`; other questions can still answer. Returned model and usage must be retained. The guide describes question instructions as text/image parts while the reference also lists JSON: use the documented shared user JSON input for a conservative common protocol and verify schema support before relying on question JSON. The reference's large field maxima are validation limits, not proof that an entire book fits or remains legible.

[OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) list Decisions as not used for training, with default abuse-monitoring retention up to 30 days and no ordinary application state, subject to exceptions. ZDR requires eligibility and configuration; it is not established for this account. Caching can retain encrypted GPU-local tensors until a 24-hour expiration, distinct from the reference's 30-minute minimum cache TTL. Image safety scanning can retain flagged inputs for manual review even under ZDR. Residency/processing and HIPAA eligibility depend on region, agreements and account configuration. Verify actual settings and caching policy before sending private material; public documentation alone does not establish the owner's controls.

The general [vision guide](https://developers.openai.com/api/docs/guides/images-vision) warns about small text, rotation, spatial precision and resizing. Original detail can still resize. Its general sizing table did not identify `gpt-6-luna` in the fetched Markdown, and the Decisions guide/reference did not settle a Decisions-specific numeric aggregate image/count/context ceiling. Do not import the general guide's 512 MB/1,500-image figures as verified Decisions limits. Exact Luna image preprocessing, token conversion, effective detail behavior and account rate limits remain prerequisites for a bounded authorized probe or provider clarification. Enlarged crops may help distinguish tiny fractions, but a successful request does not prove that those glyphs survived preprocessing.

## Verified Jev API facts

[System One](https://docs.typesafe.ai/api/system-one) uses `POST https://api.typesafe.ai/v1/systemone` with bearer authentication, `model`, structured `state`, and named `questions`; answers preserve question IDs and report model/usage. The schema provides Noul, Choice, Score and Box. No Decisions-style per-question refusal union was found in the inspected schema. Absence of that union does not establish that refusals cannot happen: preserve unexpected/error responses and never coerce them into clearance.

[Noul](https://docs.typesafe.ai/primitives/noul) returns `noul`, the estimated probability of yes, with optional true/false criteria. A value near 0.5 is uncertainty, not an explicit abstention. [Choice](https://docs.typesafe.ai/primitives/choice) returns the selected category, probabilities and confidence; add an insufficient-evidence category rather than forcing a clean/error answer. [Score](https://docs.typesafe.ai/primitives/score) is an expected ordered level with distribution and confidence, not accuracy. Confidence describes the answer distribution and does not guarantee correctness. [Box](https://docs.typesafe.ai/primitives/box) provides normalized edges and confidence, not a verified source locator or proof that text inside the box was read correctly.

[Images](https://docs.typesafe.ai/images) and Box are explicitly not production-ready; formats, limits, answers and accuracy may change. Every image/Box request requires `TypeSafe-Danger-Zone-Images: true`. Both Jev 1.13 and 1.14 accept images; Box requires 1.14. Images are assets referenced from state, instructions or criteria, sent as multipart files or base64, not arbitrary hosted URLs. PNG/JPEG still images must be 280–1568 pixels on each side, at most 16 MiB each. Request body, processed aggregate images and expanded request each have a 32 MiB ceiling; repeated references expand accounting. Invalid images fail the whole request rather than returning partial answers. Metadata is removed, EXIF rotation is not applied, and out-of-range images are rejected rather than resized. Image tokens are billed as input, but image-token estimation guidance is not yet supplied. Preserve dimensions, orientation and transforms; a 1600-pixel serving image needs a separately authorized compatible view before sending. Preparation is future work, not an action taken here.

[Models](https://docs.typesafe.ai/models) lists `jev-1.14.0` and `jev-1.13.0` at $0.042/M input tokens with output free; normal limits are 64k/request and 32k/question. State plus questions must fit both. There is no independent question-count limit. Long context requires another explicit header, permits 262k in both limits, and is documented as slower and less accurate; it should not be an automatic retry. `jev-latest` and `jev-preview` currently resolve to 1.14.0; pin the version and record the returned model. The table says text input while the image page documents experimental images: disclose that documentation inconsistency rather than treating the table as an image-production guarantee. Account rate limits are organization-specific and were not inspected.

[Request rules/errors](https://docs.typesafe.ai/api/errors) document 32 MiB bodies, UTF-8 JSON, at most 64 nesting levels, finite numbers, validation errors, 429 rate limits and 529 overload. SDK retries are enabled by default. Later trial controls must bound attempts and preserve each transport failure; retries consume time and potentially spend even when they produce no usable judgment. A malformed request is a review failure, not evidence of a clean page.

[Legal](https://docs.typesafe.ai/legal) offers enterprise ZDR through support. The [privacy policy](https://typesafe.ai/legal/privacy-policy) promises no training/fine-tuning on inputs, describes US hosting and a necessity-based personal-data retention period, not a fixed request-deletion interval. The [DPA](https://typesafe.ai/legal/data-processing), Schedule I §8, also states purpose/legal necessity for personal-data retention. Neither establishes this account's complete image/request/log/cache retention, deletion timing or residency guarantees for all source content. Obtain service-specific terms and actual account controls before sending; no-training is not no-retention.

The [invoice cookbook](https://docs.typesafe.ai/cookbooks/ocr_confidence_bounding_boxes) demonstrates page and crop checks for already extracted fields using Jev 1.14.0 and cached responses dated 2026-10-15. Its two invoices, supplied response cache and example threshold do not validate cookbook omissions, prose, recipe ownership or multi-page completeness. Do not reuse its threshold or count cache replay as new inference. A field-only checker cannot discover content never proposed as a field without a separate source-to-transcript coverage question.

## Proposed adapter-neutral evidence and questions

The following is a protocol option inferred from the verified interfaces and the [domain glossary](/Users/rick/Documents/ChatGPT/cookbook-mcp/CONTEXT.md), not existing behavior or a settled policy.

Freeze a private check package with schema version, edition/source hash, physical-page identities, candidate hash/version, ordered image hashes and dimensions, renderer identity, crop-to-page transforms, transcript span IDs, block order and proposed recipe/part/formulation membership. Bind quantities to occurrences and owners, never deduplicate equal strings. Include unresolved markers and missing dependencies explicitly. Distinguish original evidence from candidate assertions: treat all source/candidate text as data, never instructions. Record precisely which pages, regions and assembled spans each question can inspect.

Use separate questions with identical semantic criteria for both providers:

| Concern | Observable check and required scope |
| --- | --- |
| Response contamination | Does candidate text contain refusal language, summarization, commentary or instructions absent from the page? Source-authored quotations must not be treated as contamination merely for similar wording. |
| Omission | Is visible authored content absent from the candidate? Inspect source regions systematically, including sidebars, captions and prose; candidate-only field checking is insufficient. |
| Invention | Does any asserted candidate content lack visible support? Fluency and culinary plausibility are not evidence. |
| Duplication | Is a source occurrence represented more times than authored? Repeated ingredients and repeated printed text are separate legitimate occurrences. |
| Layout order | Does the proposed block sequence preserve column, table, caption and note relationships? Use full-page context plus regions; a crop alone can hide the column error. |
| Quantity and ownership | Check each number, fraction, decimal, unit, range, yield and allocation with its ingredient, stage, recipe part and formulation. Preserve source-printed inconsistency separately from transcription error. |
| Legibility | Is the supplied view sufficient to distinguish relevant glyphs and associations? Separate unreadable source from inadequate crop/render and unavailable evidence. Upscaling is not new information. |
| Assembly | With ordered adjacent pages and the assembled section, are continuations joined once, boundaries correct and required supporting work included or explicitly unresolved? Extend beyond immediate neighbors when dependencies demand it; absent pages prevent a complete-recipe conclusion. |

Run legibility/scope questions separately from error questions; an error probability alone conflates no defect with insufficient evidence. A common categorical option is `supported defect / no defect observed in supplied scope / insufficient evidence / not applicable`, with explicit rubric definitions. Predicate/Noul questions may supplement this with defect probabilities; ordinal scores may describe severity. Neither is converted into approval by this report. The negative category deliberately makes only a scoped observation, not whole-book clearance.

For every requested question retain raw private response, returned type/model/distribution/usage, request hash, question version and scope. The normalized result must distinguish answered, explicit insufficient-evidence, provider refusal, transport failure, invalid/missing answer and not-run; retain successful sibling answers without making the request globally successful. Reject wrong IDs/types, nonfinite/out-of-range values and incomplete distributions. No default-zero scores, fabricated explanations, silent truncation or silent provider substitution. Missing evidence, refusals and review failures leave content pending under the glossary. A box is a candidate check region whose transform and contents still need validation. Typed APIs do not supply a free-form source-backed rationale; evidence links should point to fixed inspected regions, not invented quotations.

Local replay cache keys should cover endpoint/provider, requested and returned model identity, complete semantic payload and image bytes, question/schema versions, rendering/crop transforms, scope and relevant transport feature headers. Retain attempt timestamps, retry reasons, cache-hit state and billing usage privately. A changed transcript, crop or rubric invalidates reuse. Provider prompt caching and local response replay are different: replay makes no new judgment, and a cache hit supplies no fresh latency measurement. Record cache effects separately; existing exact-payload ranking caching is precedent, not a full provenance contract for images.

Build a private stratified reference set from the full confirmed audit population, separating published and local candidates and preserving edition alignment. Include independently labeled clean pages, known natural defects, low-legibility and unavailable evidence, dense quantities, multi-column prose/tables, captions, recipe boundaries and multi-page dependencies. Retained text and aligned EPUB can support adjudication but do not override original-page evidence. Synthetic mutations can isolate deletion, duplication, column swaps or quantity/owner changes; report them separately from natural defects. The initial audit population is broader than any bounded comparison sample; record unsampled scopes as unknown.

Have independent source inspection establish defect presence, class, criticality, correct association and uncertainty before judges see labels. Split development and held-out evaluation by book/layout families and related page sequences so near-duplicates do not leak. Freeze questions and evidence; use common image bytes within both providers' limits for one arm, then a separately reported provider-appropriate full-page/crop arm. Supply equivalent context and semantic questions, not necessarily identical wire serialization. Compare page and assembly units separately. Keep all outcomes, including errors, refusals and abstentions, in the accounting.

Luna as reader and Decisions as judge introduces a plausible correlated-error risk, not a correlation measured here. Stratify by reader/model provenance, especially Luna fallback versus other readers. Blind judges to provider identity and reader confidence where possible. Agreement between Jev and Decisions is not independent truth either: shared low-resolution inputs, omissions and prompts can cause shared misses. Independently inspect a preselected/random sample of content both judges would clear, not only disagreements and flagged cases. Estimate joint misses against that inspection; do not multiply provider probabilities as if independence were established.

Predefine measured acceptance criteria with the owner: denominators and uncertainty intervals for detection by defect/criticality, false alarms on clean controls, false clearance under the proposed routing policy, abstention/refusal/technical-failure rates, uninspected scope, assembly completeness, review burden and usable-content coverage. Separate false-negative defect detection from false clearance caused by granting approval. Measure request and end-to-end latency including image preparation, queues, retries and cache effects, plus billed input/cache usage and total trial spend. Use book/sequence-aware uncertainty estimates; repeated questions on one page are not independent samples. Set sample sizes and numerical tolerances prospectively on the human tickets, with held-out evaluation after any later tuning. No thresholds, winner or empirical acceptance values are selected from documentation here.

A feasible first option is parallel diagnostic evaluation of both judges with no automatic approval. A second, only after missed-error validation, is bounded routing of flagged/uncertain cases to source inspection. Either must show improvement against the frozen baseline on held-out evidence and disclose residual unavailable/unresolved content. If neither checker meets owner-agreed criteria, retain source review or request better evidence rather than infer completeness.
