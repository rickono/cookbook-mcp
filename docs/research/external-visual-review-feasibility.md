# External visual-review feasibility

Research for [Assess external visual-review feasibility within the agreed evidence scope](https://github.com/rickono/cookbook-mcp/issues/63), checked **October 27, 2026 (America/Chicago)** against current official documentation. This is desk research and a candidate pilot specification, not a service selection, spending authorization, implementation, or accuracy result. No book content was transmitted; no inference, OCR, ingestion, rendering, paid request, dependency preparation, or configuration change was performed.

## Finding and scope

Two first-party API configurations can accept selected source images together with candidate text: **OpenAI Responses with GPT-5.6 Terra** and **Anthropic Messages with Claude Sonnet 5.5**. Both are technically plausible review candidates; neither provider's documentation establishes accurate cookbook transcription, completeness detection, quantity associations, or appropriate abstention. Prefer evaluating one service first to avoid multiplying transfers and correlated reviews. The concrete configuration below uses Terra for its documented original-detail input and explicit cache controls, not because it has demonstrated higher accuracy.

The governing decisions require every physical page to receive source review, including apparently clean native text and unflagged OCR. Selected images, relevant neighboring context, and complete candidate text in the inspected scope may be planned for external review; whole-book uploads are not the default. Service, controls, and a spending limit must be settled before a trial transfers content. Initial review plus at most two additional recovery attempts per problematic region and six per physical page are shared across tools, failures, and timeouts. [Review authority resolution](https://github.com/rickono/cookbook-mcp/issues/4#issuecomment-6458642261), [extraction and recovery resolution](https://github.com/rickono/cookbook-mcp/issues/6#issuecomment-6458755406).

This report follows the existing [source-safe research convention](https://github.com/rickono/cookbook-mcp/blob/8b0dbd97841b0a40e3129e9e3b8baea596790ece/docs/research/pdf-agent-review-options.md). Project facts are read at revision `34d88711fb529b181bb33e6d71f3a50ab40dff81`; the owner's current glossary was also consulted read-only. Its uncommitted changes are not reproduced here. This shortlist is not an exhaustive cloud procurement survey; consumer chat interfaces and cloud resellers would require separate product-specific control and billing checks.

OpenAI warns about small/non-Latin text, rotation, precise localization, and incorrect image descriptions. Its image input uses `ceil(width/32) × ceil(height/32)` patches with a 1.2 multiplier for Terra. Anthropic uses `ceil(width/28) × ceil(height/28)` visual tokens after applicable resizing, warns that small or rotated images can be misread, and describes localization as approximate. Neither warning is removed by a large context window. [OpenAI vision and tokenization](https://developers.openai.com/api/docs/guides/images-vision), [Anthropic vision and limits](https://platform.claude.com/docs/en/build-with-claude/vision).

**Implication, not a measured result:** a request can satisfy the file-size limit while reducing a fraction or table label below readable scale. Full-page context and a legible crop serve different purposes: context supports omissions and recipe ownership; a crop supports small glyphs. Retain both and map all crops to the original physical page. Do not treat model-generated coordinates or a syntactically valid response as exact evidence. Preserve independent candidate geometry and competing readings required by the routing decision.

GPT-4.1 remains documented but has a scheduled January 14, 2027 shutdown, so it is not the proposed pilot dependency. This illustrates why model identity and deprecations must be rechecked before execution. [OpenAI deprecations](https://developers.openai.com/api/docs/deprecations#2026-10-14-gpt-4-series-model-deprecations).

## Data handling and account controls

### OpenAI API

API inputs/outputs are not used for training by default unless the customer opts in. Default abuse-monitoring content may remain up to 30 days, with legal/harm exceptions. Responses stores application state by default; explicitly use `store:false`. That does not disable abuse logs. Zero Data Retention (ZDR) and Modified Abuse Monitoring require prior approval and have endpoint/model exceptions; image/file inputs flagged as potential CSAM can be retained for manual review even under those controls. Regional processing is eligibility-, endpoint-, and model-dependent, not inferred from an account's address. [API data controls](https://developers.openai.com/api/docs/guides/your-data).

Prompt caching is a separate control. For GPT-5.6 and later, `prompt_cache_options.mode:"explicit"` with **no breakpoints** creates no cache writes or cache use. Default implicit caching can write context, including images; its standard 30-minute write rate is 1.25 times ordinary input, and the selected minimum lifetime is not a deletion deadline. Do not claim that `store:false` disables caching. [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).

Projects, scoped roles, and API permissions can separate this pilot from other workloads. Use a dedicated project and minimally privileged API identity rather than an administrator credential. The actual organization's model access, verification requirements, retention eligibility, permissions, and region were not inspected. [Platform permissions](https://developers.openai.com/api/docs/guides/rbac).

Current docs distinguish spend alerts from **enforced hard organization/project limits**. A hard limit returns 429 after tracked spend reaches it, but propagation can allow slight overspend. An alert alone continues traffic. This report sets neither control and supplies no dollar authorization; a future pilot also needs its own request/token reservation ledger. [Spend limits](https://developers.openai.com/api/docs/guides/spend-limits).

### Anthropic API

Commercial data is not used to train models unless the customer participates in the development partner program or explicitly supplies feedback/opts in. Do not send book-derived failure examples through thumbs-up/down or support attachments as part of a pilot. [Commercial training policy](https://privacy.claude.com/en/articles/7996885-how-do-you-use-personal-data-in-model-training).

The commercial retention policy says API inputs/outputs are deleted within 30 days, except longer-lived features, agreements, policy enforcement, and law. Flagged inputs/outputs can remain up to two years; safety scores up to seven years. Submitted feedback can remain five years. The vision FAQ's description of ephemeral image uploads must not be read as a universal zero-retention contract. [Commercial retention policy](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data).

ZDR is an organization arrangement requested through sales. Messages is eligible; Files and Batches are not. Consumer interfaces and Console playground are outside that arrangement. Current API retention documentation also says ordinary conversation content is not retained by default, while pointing to the commercial policy above. This desk review cannot reconcile the scope of those statements for this account: conservatively plan for the commercial 30-day policy unless a verified agreement establishes otherwise. Sonnet 5.5 is absent from the current list of Covered Models requiring retention; changing to a listed Fable/Mythos model could invalidate a ZDR configuration. Flagged-content and legal exceptions remain. [API arrangements and feature eligibility](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention).

Dedicated workspaces support scoped keys, membership roles, spend/rate limits, and usage reporting. Current direct Messages requests encountering a user-set spend limit return 400; tier spend caps return 429. Check error details rather than retrying every 429. Actual account limits and ZDR availability remain unverified. [Workspace controls](https://platform.claude.com/docs/en/manage-claude/workspaces), [spend/rate-limit behavior](https://platform.claude.com/docs/en/api/rate-limits).

**Owner choice:** accept a verified standard-retention arrangement or require separately approved ZDR; decide whether regional processing is required. Neither provider's no-training default establishes no storage, no safety review, or authority to transmit the evidence. Scope approval must cover candidate text and neighboring images as well as crops. Base64 is transport encoding, not a privacy boundary.

## Pricing and failure accounting

Standard on-demand USD rates checked on the research date:

| Model | Uncached input / million tokens | Output / million tokens | Additional assumptions |
| --- | ---: | ---: | --- |
| GPT-5.6 Terra | $2 | $12 | Short context, at most 272K input. Cache writes use their own rate; the proposed configuration disables cache use. |
| Claude Sonnet 5.5 | $2 | $10 | Standard service; no cache writes or paid tools assumed. |

Sources: [OpenAI pricing](https://developers.openai.com/api/docs/pricing), [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing). Image tokens are input tokens; the estimate below includes them. No batch, caching, promotional credits, subscription allowance, or negotiated discount is assumed. Taxes, currency conversion, human labeling time, local preparation/storage, and any separately negotiated retention/region costs are excluded. Reconfirm the actual account price before execution.

OpenAI reasoning tokens are charged as output. An incomplete response can consume input and reasoning tokens before producing visible text. Its error guidance does not establish a blanket free-failure rule for standard Responses requests. The Flex guide expressly exempts its resource-unavailable error, but that narrower rule must not be generalized to the standard pilot. Reserve unknown/time-out costs until reconciled against provider usage. [Reasoning cost and incomplete responses](https://developers.openai.com/api/docs/guides/reasoning#allocating-space-for-reasoning), [error codes](https://developers.openai.com/api/docs/guides/error-codes), [Flex's specific billing exception](https://developers.openai.com/api/docs/guides/flex-processing).

Anthropic documents no charge for failed requests, **but a client disconnect or timeout during a request on track to succeed is still charged**. A successful but wrong, refused, truncated, or unusable response must not be assumed free. Reconcile recorded usage and billing rather than equating review failure with provider failure. [API billing](https://support.claude.com/en/articles/8977456-how-do-i-pay-for-my-claude-api-usage).

Anthropic's SDK retries transient errors twice by default; OpenAI documents two automatic retries for 408 timeouts. In a future adapter, disable SDK retries and route every transmitted attempt through the shared region/page ledger. Backoff does not grant another attempt. Record request ID, attempted scope, error/status, usage, and reserved/settled cost privately. A provider's financial credit does not restore the project's consumed recovery attempt. A budget/credential/access failure stops work pending correction; exhausted technical attempts remain a **review failure**, not evidence of unreadable source content. [Anthropic errors and retries](https://platform.claude.com/docs/en/api/errors), [OpenAI timeout behavior](https://developers.openai.com/api/docs/guides/flex-processing#api-request-timeouts), [governing recovery policy](https://github.com/rickono/cookbook-mcp/issues/4#issuecomment-6458642261).

## Concrete candidate pilot, conditional on owner decisions

This is a review-only proposal for later authorization, not an instruction to run now.

1. **Freeze 24 target physical pages in three varied private page windows**, with independent references prepared before reviewer results. Include clean native text, hidden-layer corruption, small fractions, omissions, columns/tables, image captions, continuations, source-printed inconsistency, and genuinely unreadable content. Select both flagged and unflagged pages. The number is a feasibility sample, not a statistically justified acceptance sample. Every target page receives full-page review; seeing a neighbor as context does not automatically count as reviewing it. No edition receives whole-book approval from this sample.
2. **Service/configuration:** direct OpenAI Responses, exact documented model ID `gpt-5.6-terra`; `detail:"original"` per image; `reasoning.effort:"low"`; `service_tier:"default"` (standard processing), no tools or background mode; `store:false`; explicit cache mode without breakpoints; SDK retries disabled. Use a dedicated project and owner-approved account controls. These settings are a candidate to validate, not a proven optimal reviewer. Record effective model/settings; no unapproved model/service fallback.
3. **Evidence envelope:** one complete composed target-page image, up to two relevant full neighboring pages, and up to two targeted crops. Cost geometry assumes full images at 1,600 × 2,400 pixels and crops at 1,000 × 1,000. Carry complete candidate text for the inspected scope, retained alternatives, geometry/transforms, physical-page IDs, evidence hashes, and attempts already consumed. These dimensions are accounting assumptions, not permission to change rendering or resource ceilings. Smaller crops can use existing bounded regional evidence; unreadable input remains unresolved. Proposed transport is inline data, without Files API, public image URLs, or whole PDFs.
4. **Admission:** cap the proposed serialized request at 20 MB, account for Base64 expansion, and check all image dimensions and input tokens before transfer. Use a planning envelope of 20,000 input tokens and `max_output_tokens:8000`, including reasoning. If complete context does not fit, pause and re-plan; do not silently truncate candidate text or omit context. The 8K output choice may produce incomplete results: OpenAI recommends initially reserving 25K for reasoning/output experiments. Treat truncation as pending review failure and revise the future plan explicitly rather than silently raising its allowance. [Output allocation guidance](https://developers.openai.com/api/docs/guides/reasoning#allocating-space-for-reasoning).
5. **Output and assessment:** request inspected scope, visible mismatches/omissions, exact supported corrections tied to supplied evidence IDs, unresolved content, source-printed inconsistencies, continuation needs, and failure state. Keep prompt/schema generic and all book-derived responses private. Compare quantities at their individual occurrences and associations, not only string presence. Independent human validation measures missed errors on clean pages, unsupported changes, omissions/order/table/continuation errors, abstention, elapsed time, billed tokens, and escalation burden. A valid schema and model agreement do not establish truth. Agent approval remains disabled pending the acceptance decision and independent validation.
6. **Stopping and budget:** preserve the initial review plus two recovery attempts per problematic region, six per page, including any local alternative recovery. A retry changes useful evidence or method; stop early on plainly unreadable pixels. Enforce both these counters and the owner-chosen dollar allowance before dispatch. Reserve the next call's token envelope and unknown timeout liabilities; do not reset counters by switching models, SDKs, or regions. Shared local recovery reduces remaining external calls.

All local preparation would still use the admitted network-disabled launcher and unchanged ceilings. External transmission requires a separately authorized path outside that job; this report proposes no network exception, bypass, or automatic local-model fallback. Existing [PDF trial methods](https://github.com/rickono/cookbook-mcp/blob/34d88711fb529b181bb33e6d71f3a50ab40dff81/docs/pdf-corpus-trials.md) distinguish probe recovery from completeness; [resource isolation](https://github.com/rickono/cookbook-mcp/blob/34d88711fb529b181bb33e6d71f3a50ab40dff81/docs/ocr-resource-isolation.md) remains mandatory. The existing [review prototype](https://github.com/rickono/cookbook-mcp/blob/34d88711fb529b181bb33e6d71f3a50ab40dff81/docs/scanned-transcription-review.md) distinguishes source review from approval; the [OCR review/publication gate](https://github.com/rickono/cookbook-mcp/blob/34d88711fb529b181bb33e6d71f3a50ab40dff81/docs/ocr-review.md) is not repurposed here.

### Reproducible cost estimate, not an authorized cap

For the proposed Terra envelope, each full page uses `ceil(1600/32) × ceil(2400/32) × 1.2 = 4500` image tokens. Each crop uses `ceil(ceil(1000/32) × ceil(1000/32) × 1.2) = 1229`. Three pages plus two crops therefore use **15,958 image tokens**. Assume another **3,500 input tokens** for all text, instructions, and schema: **19,458 input tokens per call**. Assume **2,000 total output tokens**, including hidden reasoning. These are planning assumptions; actual serialized/tokenized evidence and usage must be measured. The individual images are below the documented original-detail patch rejection limit.

At $2/M input and $12/M output, one such call costs `(19458 × 2 + 2000 × 12) / 1000000 = $0.062916`:

- 24 initial calls: **about $1.51**.
- Illustrative 25% retry incidence (six extra calls): **about $1.89**. This rate is assumed, not measured.
- 24 initial calls plus all six page-level recoveries on every target: **168 calls, about $10.57** at the same average output. This upper call count requires enough distinct problematic regions to respect the separate two-recovery limit; it is not a retry allowance for a single region.
- Using 20,000 input and the full 8,000-output envelope on all 168 calls: **about $22.85**. This is a conservative token projection under the stated configuration, not a provider invoice guarantee or an owner-approved limit.

For sensitivity, leaving default 30-minute implicit caching enabled and conservatively pricing all 20K input tokens as writes would raise that last projection to **about $24.53** (`168 × (20000 × $2.50/M + 8000 × $12/M)`). Choosing 25K rather than 8K output would raise the no-cache projection to **about $57.12**. Both changes require re-planning; neither is silently included. Repeated neighboring pages are charged on each uncached request. No book-count or whole-library cost follows from these figures without measured page counts, required contexts, token distributions, and recovery rates.

## Owner decisions and remaining evidence gaps

The desk-research question is answered: both configurations support the agreed evidence *shape*, with material fidelity, retention, and billing qualifications. The following remain for live owner decisions or later authorized evidence work:

- **Service and account:** which exact API/model/project may process the selected evidence? Is the shortlist sufficient, or is a separately researched provider/region required? Verify actual access and effective model identity before any book transfer.
- **Data controls:** is standard retention with its exceptions acceptable, or is verified ZDR required? What regional processing and local evidence/log retention are required? Resolve Anthropic's documentation scope discrepancy if that route is chosen. Verify account-specific eligibility rather than inferring it from public docs.
- **Spending:** what actual dollar allowance, alert/hard-limit configuration, timeout reserve, and stop behavior does the owner authorize? Is the 24-page, 8K-output proposal acceptable, or should its scope/output envelope change? Estimated consumption is not a purchase amount or spending authorization.
- **Independent validation:** what reference construction, sample expansion, missed-error and unsupported-correction thresholds enable agent approval? How are unreadable content, unavailable content/terminal refusal, human edge cases, and technical review failures handled without falsely completing a recipe? These are acceptance/rollout questions; this report decides none of them.

No actual account, contractual arrangement, invoice, image legibility, model output, latency, refusal behavior, accuracy, or workload reduction was tested. The existing sampled trials are not independent validation of this configuration. Documentation can change after the checked date; recheck service limits, lifecycle, controls, and prices at pilot authorization. Research closure supplies facts for those decisions and does not enable agent approval or publication.
